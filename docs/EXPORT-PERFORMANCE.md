# Экспорт Capcon

В окне экспорта доступны H.264 и HEVC. Переключатель «Аппаратное ускорение»
включён по умолчанию: на macOS первым пробуется VideoToolbox, при отказе —
программный кодировщик. Выключенный переключатель отдаёт предпочтение x264
или x265. Телефоны продолжают использовать системные кодировщики.

Аппаратный вариант не всегда самый быстрый: результат зависит от материала,
разрешения и обработки кадров. Разрешение проекта и частота кадров не меняются.

## Что ускорено

- Отрисовка и преобразование/кодирование работают в двух потоках. В очереди
  находится не более одного кадра, поэтому она не накапливает весь ролик в RAM.
- Буферы RGBA и YUV используются повторно. Перед записью в YUV проверяется
  исключительное владение: кадры, ещё удерживаемые кодировщиком, не перезаписываются.
- При чтении из GPU удалено обнуление целого кадра перед копированием его пикселей.
- Отмена и ошибки завершают поток кодирования до удаления временных файлов.

Полностью исключить передачу изображения из GPU в CPU эти изменения не пытаются:
для этого нужен отдельный путь передачи Metal/CVPixelBuffer в VideoToolbox.

## Локальный замер

Apple M3 Max, macOS 15.7.9; первые 8 секунд сохранённого проекта с субтитрами,
2160×3840, 24 fps, 26,2 Mbps, 192 кадра. Кэш субтитров прогрет. Время включает
экспорт видео, аудио и сборку MP4, подготовка субтитров измеряется отдельно.

| Вариант | Время |
| --- | ---: |
| H.264 до изменений, x264 | 8,49 с |
| H.264 после изменений, VideoToolbox | 4,59 с |
| HEVC после изменений, VideoToolbox | 4,33 с |
| H.264 после изменений, x264 | 5,32 с |

Это предварительные замеры одного короткого участка, не прогноз времени полного
ролика. Для программного H.264 сравнение декодированных изображений до/после
дало SSIM 0,997. Размер, частота кадров, количество кадров и звуковая дорожка
проверены через ffprobe.

## Повторение замера

Пример `concat-host/examples/export_bench.rs` читает сохранённый проект, не
сохраняя его. Первые несколько секунд экспортируются с субтитрами; исходный
проект не обрезается. Выходной файл должен отсутствовать. Кэш заголовков
создаётся рядом с результатом в `title-cache/`.

```sh
cd src
cargo run --locked --profile quick -p concat-host --features gpu \
  --example export_bench -- '/path/to/project' /tmp/sample-h264.mp4 h264 8
cargo run --locked --profile quick -p concat-host --features gpu \
  --example export_bench -- '/path/to/project' /tmp/sample-hevc.mp4 hevc 8
# Для программного кодирования добавьте последним аргументом software.
```

В журнале приложения теперь видны выбранный кодировщик, подготовка субтитров,
время декодирования, отрисовки/чтения GPU, преобразования/кодирования и ожидания
очереди. Эти времена частично перекрываются и не должны складываться.

## Проверки

Проверяются порядок кадров, отмена, ошибки и падение кодировщика, а также
сохранность кадров при задержанном кодировании x264.

Две прежние ошибки HDR-декодирования (`filter graph: Invalid argument`)
исправлены: фильтру `scale` передавалось имя матрицы `bt2020nc`, а он принимает
`bt2020`. Исправлены оба пути: преобразование HDR в SDR и чтение 16-битных
HDR-кадров для GPU. Это имя описано в [документации FFmpeg](https://www.ffmpeg.org/ffmpeg-filters.html#scale).

Полные наборы `concat-media` и `concat-export` прошли без исключения HDR-тестов:
114 и 42 успешных теста соответственно; один тест media штатно помечен ignored.
Дополнительно прошли оба теста HLG-экспорта в HDR/SDR и Clippy затронутых модулей.
